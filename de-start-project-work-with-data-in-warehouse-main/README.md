# 🗄️ DWH Data Mart: Отчет по клиентам (Customer Report)

Этот проект представляет собой реализацию ETL-процесса для формирования аналитической витрины данных (Data Mart) в PostgreSQL. Витрина агрегирует информацию о заказах, клиентах и мастерах для последующего построения отчетов.

## 🎯 О проекте

Главная особенность проекта — **инкрементальная загрузка (Incremental Load)**. Скрипт не пересчитывает всю базу данных с нуля при каждом запуске, а обрабатывает только те заказы, клиенты, товары и мастера, которые были изменены с момента последней успешной загрузки. Это значительно экономит ресурсы сервера и время выполнения.

### Что рассчитывает витрина (`customer_report_datamart`):
Для каждого клиента в разрезе отчетного месяца (`report_period` в формате `YYYY-MM`) вычисляются:
* **Финансовые показатели:** Общая сумма покупок клиента (`customer_money`) и доход платформы, который составляет 10% от этой суммы (`platform_money`).
* **Статистика заказов:** Общее количество заказов, средняя стоимость одного заказа.
* **Медианное время выполнения:** Рассчитывается с помощью статистической функции `PERCENTILE_CONT(0.5)` как медианное количество дней от создания до завершения заказа.
* **Популярность:** Самая часто заказываемая категория товаров (`top_product_category`) и самый популярный мастер (`top_craftsman_id`) — вычисляются через оконную функцию `RANK()`.
* **Статусы заказов:** Количество созданных, находящихся в процессе, в доставке, завершенных и незавершенных заказов.

## 🛠 Технологии и инструменты
* **СУБД:** PostgreSQL
* **Аналитические функции:** `RANK() OVER (PARTITION BY ...)`, `PERCENTILE_CONT()`.
* **Агрегация:** `SUM`, `COUNT`, `AVG`.
* **CTE (WITH):** Декомпозиция сложного запроса на логические шаги (получение дельты, агрегация, вычисление топов, обновление).
* **Инкрементальная логика:** Использование таблицы водяных знаков (watermark) `load_dates_customer_report_datamart` и условий `COALESCE(MAX(load_dttm))` для фильтрации только новых данных.
* **UPSERT-логика:** Разделение потока на `INSERT` (для новых записей) и `UPDATE` (для существующих) с использованием `NOT EXISTS` для предотвращения дублей.

* `README.md` — описание проекта.

## 🚀 Как это работает (Алгоритм)
1. **Поиск изменений (Delta):** Система смотрит на максимальную дату загрузки в таблице `load_dates_customer_report_datamart` и выбирает из фактов и измерений (`f_order`, `d_customer`, `d_product`, `d_craftsman`) только те строки, которые были обновлены позже этой даты.
2. **Агрегация:** Собранные данные группируются по клиентам и месяцам, вычисляются суммы и средние значения.
3. **Определение лидеров:** Через оконные функции определяются топ-1 категория и топ-1 мастер для каждого клиента.
4. **Запись в витрину:** Данные добавляются как новые строки (если такого клиента за этот месяц еще нет) или обновляют уже существующие.
5. **Фиксация даты:** В таблицу `load_dates` записывается новая максимальная дата загрузки, чтобы при следующем запуске система снова понимала, откуда начинать.
